# 版本控制思维

## Git 不是什么

Git 不是"网盘"或"备份工具"。它是一个**内容寻址的文件系统**——每个文件版本都由其内容的哈希值（SHA-1）唯一标识。

## Git 的核心模型

### 三种状态

1. **工作区**（Working Directory）：你正在编辑的文件
2. **暂存区**（Index/Stage）：准备提交的变更
3. **仓库**（Repository）：已提交的历史记录

### 提交 = 快照

每次 `git commit` 不是保存"差异"，而是保存整个项目的一个**完整快照**。

```
commit  →  tree  →  blob ("hello world")
          tree  →  blob ("console.log('hi')")
```

## 分支：轻量级移动指针

Git 的分支只是一个指向某个提交的指针。创建分支几乎零成本——这就是为什么在 Git 中频繁分支是好的实践。

## 思维方式

- 每个提交应该是逻辑上独立的、可理解的变更
- 提交信息应该解释"为什么"，而不是"做了什么"
- 频繁提交，频繁推送——不怕犯错
